COURSE 01 • START HERE

Computer Foundations

Understand what a computer is doing before learning how to protect it.

LESSON 0115 MIN • BEGINNER

From input to information

A computer receives input, follows instructions, stores data, and produces output. A keyboard provides input; the processor follows instructions; memory holds active work; storage keeps files after power is turned off; and a screen produces output.

Security becomes easier when you know where information travels. Data may be stored on a drive, processed in memory, displayed by an application, or sent across a network. Each location needs suitable protection.

CPU

Follows program instructions and performs calculations.

RAM

Fast, temporary working space for running programs.

STORAGE

Keeps the operating system, applications, and files.

NETWORK

Moves data between devices using agreed rules.

SAFE ACTIVITY

Open your computer’s system information page. Write down the operating system, installed memory, and storage size. Do not share serial numbers or account details.

Quick check: Which component normally holds active work temporarily?

LESSON 0220 MIN • BEGINNER

Files, processes, accounts, and permissions

An operating system manages hardware and gives applications a controlled way to use it. A file stores data under a name and location. A process is a running instance of a program. An account connects actions to a user, while permissions decide what that user or process may read, change, or run.

File extensions such as .txt, .html, and .py suggest a file’s format, but the extension alone does not prove that a file is safe. Avoid opening unexpected downloads and keep important files backed up.

EXAMPLE PATHDocuments/SECTO/notes.txt

This describes a file named notes.txt inside a SECTO folder, which is inside Documents.

SAFE ACTIVITY

Create a folder named SECTO-Lab in Documents. Inside it, create notes.txt and write one sentence about what an operating system does.

Quick check: What is a program called while it is running?

COURSE 02 • CODING

Python from Zero

Learn how a program stores information, makes decisions, and repeats useful work.

LESSON 0320 MIN • BEGINNER

Variables and data types

A variable is a readable name that points to a value. Python chooses a data type from the value you assign. Text is a string, a whole number is an integer, and True or False is a Boolean.

device_name = "study-laptop"
failed_logins = 2
account_locked = False

print(device_name)
print(failed_logins)

Clear names make programs easier to review. Avoid placing real passwords, secret keys, or private information directly inside source code.

SAFE ACTIVITY

On paper or in a local Python editor, create variables for a fictional device name, update count, and whether backup is enabled. Print the three values.

Quick check: Which type stores True or False?

LESSON 0420 MIN • BEGINNER

Conditions and loops

A condition lets a program choose a path. A loop repeats a block of instructions. In Python, indentation shows which instructions belong together.

update_status = ["installed", "pending", "installed"]

for status in update_status:
    if status == "pending":
        print("Review this update")
    else:
        print("No action needed")

The loop checks each fictional status. The condition compares the current value with "pending". This pattern is useful for organizing defensive checks without touching any outside system.

SAFE ACTIVITY

Change the fictional list to contain four statuses. Predict the four output lines before running it, then compare your prediction with the result.

Quick check: Which keyword repeats the block for every item?

COURSE 03 • SYSTEMS

Linux Essentials

Use a terminal carefully and understand how Linux organizes access.

LESSON 0520 MIN • BEGINNER

Your first safe terminal commands

A command-line interface accepts text instructions. The shell reads a command, separates the command name from its options and arguments, and asks the operating system to perform the allowed action.

pwdShow the current folder.
lsList items in the current folder.
mkdir secto-labCreate your own practice folder.
cd secto-labMove into that folder.
touch notes.txtCreate an empty practice file.
SAFE ACTIVITY

Use only the commands shown above in your own home/Documents area or an approved training terminal. Check your location with pwd before creating anything.

Quick check: Which command shows your current location?

LESSON 0620 MIN • BEGINNER

Users, groups, and permissions

Linux commonly describes file access with three actions: read, write, and execute. Those permissions may be set for the file owner, a group, and everyone else. This supports the principle of least privilege: give an account only the access needed for its task.

-rw-r--r--  1 learner students  84  notes.txt

In this example, the owner may read and write. The group and others may only read. The first character describes the item type; the next nine characters appear in three permission groups.

SAFE ACTIVITY

Run ls -l inside your own SECTO practice folder and identify the owner’s first three permission characters. Do not change system files or permissions.

Quick check: What means giving only the access needed?

COURSE 04 • NETWORKS

Networking Explained

Follow a web request from a human-readable name to a service.

LESSON 0720 MIN • BEGINNER

IP addresses, DNS, and packets

Devices use network addresses to exchange data. An IP address identifies a network destination. The Domain Name System, or DNS, helps translate a readable domain name into information a device can use to find the correct service.

Browser1DNS lookup2IP destination3Web server

Large messages are divided into smaller units often called packets. Networking protocols define how systems format, send, receive, and interpret those units. Reliability and security depend on more than one layer working together.

SAFE ACTIVITY

Draw the four-step flow above. Under each step, write what question is being answered: “What name?”, “What address?”, “Where should data go?”, and “Which service responds?”

Quick check: Which system connects domain names with destination information?

LESSON 0820 MIN • BEGINNER

Protocols, ports, and web requests

A protocol is an agreed set of communication rules. A port number helps a device direct incoming traffic to the correct network service. The number identifies a service endpoint; it is not a physical socket.

HTTPS • 443

Encrypted web communication.

DNS • 53

Name and address information.

SSH • 22

Secure remote administration when authorized.

HTTP • 80

Unencrypted web communication.

When you open a secure website, the browser usually resolves the name, connects to the server, establishes protected communication, sends a request, and interprets the response.

SAFE ACTIVITY

Match each service above with its typical port. This is a memory exercise only—do not probe or scan networks.

Quick check: Which port is commonly associated with HTTPS?

COURSE 05 • DEFENSE

Cybersecurity Essentials

Think in terms of risk, then apply everyday protections that reduce it.

LESSON 0915 MIN • BEGINNER

Security goals and risk

Security is not simply “blocking hackers.” It is managing risk to information and services. Three useful goals are confidentiality (only authorized access), integrity (accurate and trustworthy data), and availability (systems and information are usable when needed).

NIST’s Cybersecurity Framework organizes outcomes into six broad functions: Govern, Identify, Protect, Detect, Respond, and Recover. For a beginner, this is a reminder that good security includes preparation, protection, awareness, action, and learning—not one magic tool.

CConfidentiality
IIntegrity
AAvailability
SAFE ACTIVITY

Imagine a school assignment stored online. Write one example of losing confidentiality, one of losing integrity, and one of losing availability. Do not use real names or private incidents.

Quick check: Which goal focuses on data remaining accurate?

LESSON 1020 MIN • BEGINNER

Strong accounts, updates, and phishing awareness

Use a unique password or passphrase for every important account and store them in a trusted password manager. Turn on multifactor authentication (MFA), which asks for another proof in addition to a password. Install software updates because they often fix known security weaknesses.

Phishing messages try to create urgency, fear, or excitement so a person acts without checking. Pause before opening unexpected links or attachments. Verify important requests using a contact method you already trust—not contact information provided by the suspicious message.

01

Slow down. Urgency is a reason to verify.

02

Check context. Was the message expected?

03

Verify separately. Use a known website or phone number.

04

Report. Use the platform or organization’s reporting option.

SAFE ACTIVITY

Review the security settings of one account you own. Check whether MFA and automatic updates are enabled. Ask a parent, guardian, teacher, or administrator before changing a managed account.

Quick check: How should you verify an unexpected important request?

COURSE 06 • WEB

Secure Web Development

Learn the three browser languages, then add security from the beginning.

LESSON 1120 MIN • BEGINNER

HTML, CSS, and JavaScript

HTML describes the structure and meaning of content. CSS controls presentation and layout. JavaScript adds behavior and interactivity. Keeping these roles understandable makes a website easier to maintain and review.

<article>
  <h2>Password safety</h2>
  <p>Use a unique passphrase for each account.</p>
  <button type="button">Mark complete</button>
</article>

Semantic elements such as header, nav, main, and article communicate purpose. Labels, keyboard access, readable contrast, and responsive layout help more people use the site.

SAFE ACTIVITY

Create a local HTML file containing one heading, one paragraph, and one button. Open it in your browser. No hosting or account is required.

Quick check: Which language gives web content its structure?

LESSON 1220 MIN • BEGINNER

Build security into the design

Browser checks improve user experience, but important validation must also happen on a trusted server because browser code can be changed by a user. Treat all external input as untrusted until it is checked for the expected type, size, format, and allowed values.

Display user-provided content using safe output methods, keep secrets out of frontend files, use HTTPS, apply least privilege, record useful security events without storing sensitive data, and show users errors that help them recover without exposing internal details.

INPUT

Accept only expected formats and limits.

ACCESS

Check permission for every protected action.

SECRETS

Keep keys and credentials on trusted systems.

OUTPUT

Render untrusted content with safe methods.

SAFE ACTIVITY

Review a form you created. List its fields, expected data type, reasonable length limit, and whether the field is required. This is a design exercise; do not test other websites.

Quick check: Where must important validation also occur?
